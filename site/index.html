Free and open source · GPL-3.0-or-later · Windows

Keeps your connection going when the network gets in the way.

DNet Engine sends your traffic through a server you run, over whichever of several connection methods works on the network you are on, and keeps going when that network changes. It was made for campus, hostel and café networks, first for its author and friends, and anyone is welcome to use it.

View the source on GitHub Read the limits first

Early software. There is no installer yet, and it has not been used on a real network. This page says what exists, what does not, and what it will never claim.

What it does

  • Picks a method by measuring

    It tries the connection methods it has against the network you are on, and uses the one that works. It does not guess from names or assume one is best.

  • Follows the network

    When the network under it changes, or a method is blocked, it moves to another path and tells you why, in plain words.

  • Fails closed

    There is no “send it direct” fallback. If the tunnel is down, traffic is not quietly sent around it. (See the kill-switch note below: this is a decision in the service, not yet a guarantee from the operating system.)

  • Puts things back

    It changes routes and name servers while it runs, writes down every change before making it, and undoes them when it stops or after a crash.

  • Is yours end to end

    Nothing here is run by the project: no servers, no accounts, no shared keys. You bring the endpoint, or let a later version set one up in your own cloud account.

  • Is plain about itself

    Every automatic change carries a reason. Anything best-effort is labelled best-effort. Claims are measured, not hoped for.

What it does not do

A tool that overstates what it does is worse than one that does less. These are the limits.

It does not hide that you use a tunnel.
It hides the content of your traffic and the protocol carrying it. It does not hide how much you send or where the tunnel’s packets go; whoever runs the network can still see that.
It does not make you anonymous.
Your traffic is encrypted to your own server, then leaves it. Whoever runs that server, and the network it sits on, can see what any server operator sees.
The kill switch is not a guarantee yet.
The service refuses to send traffic unprotected, but nothing at the operating-system level enforces that yet. A crash or a stopped service is not a promise that nothing leaves the machine.
Rules by program are best-effort.
Rules by destination are reliable. Rules by program depend on spotting the program as it connects, which can miss short-lived connections.
It is not a bypass tool.
Using a tunnel on a managed network may break that network’s rules, and the consequences are yours. It is for staying connected and protecting your traffic on networks you do not control, not for evading restrictions you agreed to. Read the policy of the network you are on.
It does not come with a server.
No endpoint, credential or key is built in. Without a server of your own it has nowhere to connect.

Try it, or help

There is nothing to download yet. If you can build Rust and run Windows, the repository explains how to build and test it, and every test that touches a network runs only against a simulated one.

  • Build and test it
  • Why it is built this way
  • The interface design system
  • Report a problem or ask a question

Found a security problem? Please report it privately to the maintainer, not in a public issue. The repository README explains how the service treats the boundary it guards.
